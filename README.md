# pricers

![python](https://img.shields.io/badge/python-3.11%20%7C%203.12-blue)
![license](https://img.shields.io/badge/license-MIT-green)

Independent implementations of the option-pricing methods a quant-dev screen asks for —
Black-Scholes with Greeks and implied vol, CRR / Jarrow-Rudd / trinomial trees, explicit /
implicit / Crank-Nicolson finite differences with PSOR and Brennan-Schwartz for American
exercise, Monte Carlo with antithetic and control variates, Longstaff-Schwartz, and the COS
method for Heston — each written out in numpy and each validated against a closed form or a
published value or QuantLib with an explicit tolerance, with convergence-*rate* tests and a
regenerable accuracy-vs-speed table. QuantLib already does all of this, faster; the point of
the repo is the verification harness and the fact that every method is written out and
tested, not to compete with QuantLib. The one design rule: no number is quoted without the
oracle it was checked against and the tolerance it met; every number in the two tables below
is produced by `pricers report` or `pricers bench` (regenerated by CI, machine named in the
bench header), and the test count and timing under *Run it* are from `pytest -q` on the same
machine.

## Run it

```bash
pip install -e ".[dev,oracle]"   # [oracle] = QuantLib 1.43, optional; its tests skip when absent
pytest -q                        # 75 tests: identities to 1e-10, oracles at stated tolerances,
                                 #   convergence rates, QuantLib cross-checks (4, skipped without
                                 #   QuantLib), bench/CLI; about 20 s on an M1 laptop
pricers report                   # regenerate the validation and convergence tables in this README
pricers bench                    # regenerate the accuracy-vs-speed table (--check: verify instead)
pricers calibrate [--noise 0.002] # Heston calibration demo: recover known parameters from a surface
pricers price --method fd-cn --S 50 --K 50 --T 0.4166667 --sigma 0.4 --r 0.10 --right P --american --n 800
# 4.284071  (fd cn n_x=800 n_t=800 american bs)      Hull's American put; converged value 4.2842
```

## What it computes

| module | method | exercise | validated against |
|---|---|---|---|
| `bs` | Black-Scholes-Merton price, Greeks (vega per 1.00 vol, theta per calendar day, rho per 1.00), implied vol by Brent and a vectorised Newton inverter (`implied_vol_vec`, NaN below the information floor); arrays broadcast | European | closed form recomputed with scipy and QuantLib, Hull's worked example, Fang & Oosterlee Table 2, finite-difference Greeks, parity to 1e-10 |
| `trees` | CRR (exact p, and QuantLib's first-order p), Jarrow-Rudd, Kamrad-Ritchken trinomial; BBS smoothing; Richardson | European, American | Black-Scholes with the 2.2/N bound and the sign flip between N and N+1; Hull's 5-step put 4.49 and its converged 4.2842; QuantLib binomial engines to 1e-10 |
| `fd` | log-spot grid, theta-scheme (explicit / implicit / CN) with Rannacher start-up; American by PSOR (reference) or Brennan-Schwartz (fast, puts); bump Greeks | European, American | second-order CN error ratio; all 20 Longstaff-Schwartz Table 1 cases vs a continuous-American reference to 1e-3; PSOR == Brennan-Schwartz to 1e-6; QuantLib QdFp on an off-fixture case |
| `mc` | seeded GBM terminal values and paths; plain, antithetic, S_T control variate with the optimal beta, both; price, s.e., 95% CI; Longstaff-Schwartz put (Laguerre basis, ITM regression) | European, American put | exact sd of the discounted payoff (14.7194 / 8.6576) and the control-variate variance factor 0.1453; 3-s.e. coverage at fixed seeds; the paper's LSM column within combined s.e. |
| `heston` | COS (Fang & Oosterlee) with the Albrecher / Gatheral characteristic function; truncation range at ln(S/K) + c1 with closed-form c1, c2 and numeric c4, N = 1024 by default; generic `cos_price(cf, ...)` also prices GBM | European | the paper's eq. (53) values at T=1 and T=10 to 1e-6 (Feller violated), Andersen Case I, QuantLib COS and analytic Heston engines at the money and 6-38 sd away, a Feller-violated high vol-of-vol case that needs N=1024 |

Two findings the harness produced while being built, both recorded in
[docs/DESIGN.md](docs/DESIGN.md): the CRR constants in the oracle fixture (−2.062 / +1.690)
belong to QuantLib's first-order branch probability, the textbook exact-p tree gives
−2.000 / +1.753 (both satisfy the 2.2/N bound; both forms are implemented and tested); and
the Heston c2 printed in Fang & Oosterlee's Table 11, as transcribed, is short by
η²θ(1 − e^{−κT})/(4κ³) — the variance was re-derived from the CIR covariance, checked
against the numerical second derivative of log φ to 1e-9, and the gap to the printed
formula is itself a test. Two defects the review of v0.1 found, also recorded there: the
COS truncation range was placed at c1 without the ln(S/K) shift, exact at the money (every
fixture case) and wrong beyond about 4.5 σ√T — fixed and tested out to 10 sd; and N = 256
was not enough for Feller-violated, high vol-of-vol parameters (2e-3 near the money), so the
default is now N = 1024 (0 of 400 random cases above 1e-6 against QuantLib's analytic engine).

Read the bench table for what it is: a single ATM call, best-of-three timings, on one
laptop. It shows the shape of each method's error (the CRR sawtooth is an O(1/N) error with
a parity-dependent constant, BBSR removes it, CN is O(h²), MC is O(1/√n), COS is exponential)
and roughly where pure numpy sits against QuantLib's C++ on this machine: 4-8.5x behind on
the trees, 1.2-5.2x behind on Crank-Nicolson (closing as the grid grows), ahead on the
vectorised MC. The hot paths that would benefit from Rust are named in
[docs/DESIGN.md](docs/DESIGN.md).

## Calibration

`pricers calibrate` fits Heston to an implied-vol surface by least squares in vol space on
the COS pricer (one characteristic-function evaluation per maturity — `price_strikes` —
and a vectorised Newton implied-vol inverter, so a 45-point surface evaluates in ~10 ms).
On a synthetic surface generated by known parameters, three different starting points all
recover them:

```
true      v0=0.0400 kappa=1.500 theta=0.0500 sigma_v=0.600 rho=-0.700
fitted    v0=0.0400 kappa=1.500 theta=0.0500 sigma_v=0.600 rho=-0.700 | RMSE 0.000 vol pts, max 0.000, n=45, Feller VIOLATED, 181 surface evaluations
```

With 20 bp of noise on the vols (`--noise 0.002`): RMSE 0.156 vol points — the noise, not
below it — with v0 and rho recovered to 3 decimals and kappa drifting 1.500 → 1.594, which
is the nearly flat kappa–theta–sigma_v direction every Heston calibration has. The result
reports the fit error, the Feller flag and every start's outcome because the residual, not
the five numbers, is what a desk should look at.

## Design rules

Tested:

- **Every oracle carries a tolerance and a source** — `tests/fixtures/oracle_values.json` is
  the value-collection file as recorded (no keys added or pruned), its `source` fields and
  `tests/fixtures/README.md` name every source, each test that reads it says in its docstring
  what it checks against, and `pricers report` reproduces the max error per row.
- **Identities are exact**: put-call parity to 1e-10 (Black-Scholes, COS by construction);
  American ≥ European and American put ≥ intrinsic on every tree and grid; Brennan-Schwartz
  and PSOR agree to 1e-6 on the same grid.
- **Rates, not just values**: CRR |error| ≤ 2.2/N with the parity sign flip; CN error ratio on
  doubling in [3.3, 4.7], with the strike on a node and with the spot between nodes; MC
  s.e.·√n within 10% of the exact sd; COS error falls by more than 10x per doubling of N.
- **MC is honest about noise**: every estimator returns s.e. and a CI; tests assert coverage at
  fixed seeds, and the LSM comparison uses the combined standard error of both estimates. The
  LSM s.e. is the paper's conditional one and understates by up to ~16% when the exercise
  region is large (measured over 150 seeds; docs/DESIGN.md) — read it as a floor.
- **The README regenerates**: CI runs `pricers report` and diffs it, and `pricers bench --check`
  on the deterministic error columns.

By construction (not a test): `bs` keeps deskboard's `price / greeks / implied_vol`
signatures and units, so that repo can swap its pricer for this module unchanged; tree
backward induction is a numpy expression per level, never a Python loop over nodes; PSOR is
left as the slow pure-Python reference on purpose, with Brennan-Schwartz as the fast path;
Heston calls go through the put and parity so the COS coefficients stay bounded.

## What is where

```
src/pricers/
  bs.py         Black-Scholes-Merton: price, Greeks, implied vol (deskboard API), array inputs
  trees.py      CRR / CRR-QL / Jarrow-Rudd / Kamrad-Ritchken; BBS; Richardson; TreeResult
  fd.py         log-spot grid, theta-schemes, Rannacher, PSOR, Brennan-Schwartz, bump Greeks
  mc.py         GBM simulation, four European estimators with s.e. and CI, Longstaff-Schwartz put
  heston.py     COS method (range at ln(S/K) + c1), Heston and GBM characteristic functions, cumulants
  bench.py      accuracy-vs-speed table vs closed form and QuantLib; README writer and checker
  report.py     validation and convergence-rate tables from the oracle fixture; README writer
  cli.py        pricers bench | report | calibrate | price
tests/
  fixtures/     oracle_values.json (as recorded) + README.md with the sources
  test_*.py     one file per pricing module, bench and cli share test_bench_cli.py, report.py is
                verified by CI's regenerate-and-diff step; named by what each test asserts;
                QuantLib tests skip if absent
docs/DESIGN.md  numerics choices, oracle provenance, the Rust decision, what is not done
```

## Roadmap

v0.2 (shipped): Heston calibration. Next: Rust/PyO3 hot paths for the tree induction, the Brennan-Schwartz sweep and PSOR (the
decision is made, the toolchain was not on the build machine, see docs/DESIGN.md);
Brennan-Schwartz for calls with dividends; LSMC for calls and a Bermudan variant with the
exercise dates as a parameter, and an LSM standard error that includes the regression's
sampling variance; Leisen-Reimer tree. v0.3: local vol on the FD grid,
barrier and Asian payoffs on the same three engines.

## Data and privacy

There is no market data in this repo. Every input is a textbook or paper parameter set,
recorded with its source in `tests/fixtures/oracle_values.json`; every random number comes
from a seeded `numpy.random.Generator`. Nothing here is derived from the author's trading
book or its data.
